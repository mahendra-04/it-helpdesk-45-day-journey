# Day 28 - Security Basics

**Status:** Lesson Completed

## Learning Objectives

- Understand basic security responsibilities in help desk work.
- Recognize common user-facing security risks.
- Learn when to escalate security concerns.

## Concepts Learned

- Phishing, social engineering, MFA, password hygiene, least privilege, and secure handling.
- Suspicious links, attachments, login prompts, and impersonation attempts.
- Basic incident reporting and escalation awareness.
- Importance of protecting user data and credentials.

## Real-World Help Desk Examples

- A user reports a suspicious email asking for credentials.
- A user cannot complete MFA after changing phones.
- A device displays a security alert from endpoint protection.

## Troubleshooting Workflows

1. Gather facts without clicking suspicious links or opening attachments.
2. Confirm affected user, message sender, timestamp, and reported action.
3. Advise the user to stop interacting with suspicious content.
4. Escalate through the approved security process.
5. Document indicators and user actions taken.

## Documentation Examples

- Record sender, subject, timestamp, and affected account.
- Note whether the user clicked, entered credentials, or downloaded anything.
- Avoid including sensitive secrets in ticket notes.

## Ticket Note Examples

**Issue:** User reported suspicious email requesting password confirmation.

**Technician notes:** Advised user not to click links, collected sender and timestamp, and confirmed no credentials were entered.

**Resolution:** Escalated email details to security queue and documented user guidance.

## Key Takeaways

- Help desk technicians are often the first line of security reporting.
- User guidance should be calm, clear, and immediate.
- Security tickets require careful documentation and appropriate escalation.
