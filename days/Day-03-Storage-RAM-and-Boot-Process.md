# Day 03 - Storage, RAM, and Boot Process

**Status:** Lesson Completed

## Learning Objectives

- Understand how storage and RAM affect device performance and startup.
- Learn the basic boot process from power-on to operating system load.
- Recognize common symptoms related to storage, memory, BIOS, and UEFI.

## Concepts Learned

- SSD vs HDD performance and support symptoms.
- RAM usage, paging, and memory pressure.
- BIOS/UEFI firmware role during startup.
- Boot order, operating system loader, and startup failure points.

## Real-World Help Desk Examples

- A device is slow because storage is nearly full.
- A laptop displays "no boot device" after a drive issue.
- A user experiences application freezes when RAM usage is consistently high.

## Troubleshooting Workflows

1. Ask when the startup or performance issue began.
2. Check available storage, drive health indicators, and memory usage.
3. Confirm whether the system reaches BIOS/UEFI, Windows sign-in, or desktop.
4. Review recent updates, crashes, or hardware changes.
5. Document findings and escalate hardware failures with clear evidence.

## Documentation Examples

- Include storage capacity, free space, RAM installed, and observed boot message.
- Note whether the issue is intermittent or reproducible.
- Record any recovery options attempted and their result.

## Ticket Note Examples

**Issue:** User reported laptop stuck at boot screen.

**Technician notes:** Confirmed power-on, checked BIOS boot order, verified internal drive was detected, and reviewed recent update history.

**Resolution:** Startup repair completed successfully. Device booted to Windows and user confirmed access to files.

## Key Takeaways

- Boot issues require a clear distinction between hardware, firmware, and operating system stages.
- Storage capacity and drive health are common causes of performance problems.
- RAM pressure can create symptoms that look like application failures.
