# Day 05 - Hardware Troubleshooting Framework

**Status:** Lesson Completed

## Learning Objectives

- Build a repeatable troubleshooting framework for hardware issues.
- Learn how to isolate symptoms without replacing parts too quickly.
- Document hardware findings in a way that supports escalation.

## Concepts Learned

- Symptom intake, scope review, known-good testing, and isolation.
- External vs internal hardware fault indicators.
- Power, display, storage, battery, thermal, and peripheral symptom categories.
- Escalation evidence for repair or replacement.

## Real-World Help Desk Examples

- A laptop powers off randomly during heavy use.
- A monitor works with one laptop but not another.
- A user reports clicking sounds from an external hard drive.

## Troubleshooting Workflows

1. Gather the symptom, frequency, location, and recent changes.
2. Remove nonessential peripherals and test the base device.
3. Swap one variable at a time with a known-good accessory.
4. Check logs, device status, power, heat, and physical condition.
5. Escalate with device details, tests performed, and user impact.

## Documentation Examples

- Document exact symptoms, reproduction steps, and hardware tested.
- Include photos or asset details when physical damage is relevant.
- Record whether a loaner, replacement, or warranty repair was provided.

## Ticket Note Examples

**Issue:** User reported external monitor flickering.

**Technician notes:** Tested monitor with another laptop, replaced HDMI cable, checked refresh rate, and tested docking station output.

**Resolution:** Fault isolated to HDMI cable. Cable replaced and user confirmed stable display output.

## Key Takeaways

- A hardware framework prevents guesswork and unnecessary replacements.
- Testing one variable at a time makes results more reliable.
- Escalation quality depends on clear evidence.
