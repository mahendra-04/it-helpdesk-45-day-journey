# Day 5 - Hardware Troubleshooting Framework

## Topic
Today I learned the basic framework for troubleshooting hardware problems in a structured way.

## Core Idea

A good technician does not guess. A good technician follows a process, checks simple causes first, tests one thing at a time, verifies the fix, and documents the result.

## Hardware Troubleshooting Framework

1. Identify the problem.
2. Ask questions.
3. Check physical basics.
4. Create possible causes.
5. Test one thing at a time.
6. Apply the fix.
7. Verify with the user.
8. Document everything.
9. Escalate if needed.

## Step 1 - Identify the Problem

A user may describe the issue in a vague way.

Example:

```text
My laptop is dead.
```

This could mean:

- Laptop will not power on
- Screen is black
- Battery is dead
- Charger is faulty
- Windows is frozen
- Brightness is too low
- Laptop is on but display is not working

The technician should turn vague wording into a specific problem.

## Step 2 - Ask Questions

Useful questions for hardware issues:

- When did it start?
- Did anything change recently?
- Was the device dropped?
- Was there a liquid spill?
- Is there any error message?
- Does it happen all the time or sometimes?
- Is anyone else affected?
- Did you try another cable or port?

## Step 3 - Check Physical Basics

Check simple things first:

- Power
- Cable
- Port
- Battery
- Brightness
- Volume
- Mute button
- Paper
- Ink or toner
- Physical damage
- Loose connection

## Step 4 - Create Possible Causes

Example problem:

```text
External monitor says No Signal.
```

Possible causes:

- Monitor is off
- Wrong input source selected
- HDMI cable is loose
- HDMI cable is faulty
- Laptop display mode is wrong
- Docking station is not working
- Graphics driver issue
- Monitor hardware failure

## Step 5 - Test One Thing at a Time

Testing one thing at a time helps identify what actually fixed the problem.

Bad method:

```text
Change cable, restart laptop, update driver, change monitor, and change dock all at once.
```

Good method:

```text
1. Check power.
2. Check cable.
3. Check monitor input.
4. Press Windows + P.
5. Try another cable.
6. Try another monitor.
```

## Step 6 - Apply the Fix

Examples:

- Loose cable: reconnect cable
- Wrong default printer: set correct printer
- Muted microphone: unmute microphone
- Dead battery: plug in charger
- Wrong display mode: choose Duplicate or Extend
- Stuck print job: clear print queue

## Step 7 - Verify the Fix

Always test after applying a fix.

Examples:

- Print a test page.
- Join a Teams test call.
- Type using the keyboard.
- Move the mouse.
- Confirm external monitor works.
- Ask user to confirm the issue is resolved.

## Step 8 - Document Everything

Good ticket documentation should include:

- Problem
- User impact
- Device affected
- Questions asked
- Troubleshooting steps
- Findings
- Fix applied
- Result
- User confirmation
- Escalation needed

## Step 9 - Escalate If Needed

Escalation means sending the issue to a higher-level technician or team.

Escalate when:

- Hardware is physically damaged
- Device is under warranty and needs repair
- Data loss risk exists
- Laptop will not power on after basic checks
- SSD/HDD is not detected
- Repeated issue keeps returning
- BIOS/UEFI changes are needed
- BitLocker recovery appears
- Company policy requires higher approval

## Main Rule

```text
Simple → likely → safe → deeper
```

Meaning:

- Check cable before replacing monitor.
- Check mute before reinstalling audio driver.
- Check paper before reinstalling printer.
- Check power before assuming motherboard failure.
