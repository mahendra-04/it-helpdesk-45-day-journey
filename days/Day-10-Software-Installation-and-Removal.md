# Day 10 - Software Installation and Removal

**Status:** Lesson Completed

## Learning Objectives

- Understand common Windows software installation and removal workflows.
- Learn the support impact of permissions, installers, and dependencies.
- Document application repair and reinstall steps professionally.

## Concepts Learned

- EXE and MSI installers, installation paths, app versions, and dependencies.
- Admin permissions, software center concepts, and approved application lists.
- App repair, reset, uninstall, and clean reinstall workflows.
- License and compatibility considerations.

## Real-World Help Desk Examples

- A user cannot install approved software due to missing admin rights.
- An application crashes until it is repaired or reinstalled.
- A user has the wrong version of a required application.

## Troubleshooting Workflows

1. Confirm application name, version, device, and error message.
2. Check whether the software is approved and licensed.
3. Review permissions, prerequisites, and installation logs when available.
4. Repair, update, or reinstall using approved methods.
5. Test application launch and document the result.

## Documentation Examples

- Record application name, version, installer source, and error text.
- Note whether admin rights or license assignment was required.
- Include testing steps after installation.

## Ticket Note Examples

**Issue:** User reported approved application failed to launch.

**Technician notes:** Checked installed version, reviewed Windows app settings, and ran application repair.

**Resolution:** Repair completed successfully. Application launched and user confirmed required feature worked.

## Key Takeaways

- Software support requires attention to approval, licensing, and compatibility.
- Exact error messages are important for escalation.
- Testing after repair or reinstall confirms the user can resume work.
