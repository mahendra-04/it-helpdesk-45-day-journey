# Day 22 - Password Resets and Account Lockouts

**Status:** Lesson Completed

## Learning Objectives

- Learn secure password reset and account lockout workflows.
- Understand common causes of repeated account lockouts.
- Communicate identity support steps clearly to users.

## Concepts Learned

- Identity verification, password reset policies, temporary password handling, and MFA.
- Account lockout causes such as saved passwords, mobile mail apps, VPN clients, and mapped drives.
- Password history, complexity, and expiration awareness.
- Security-sensitive ticket documentation.

## Real-World Help Desk Examples

- A user forgets their password before starting work.
- A user changes a password but keeps getting locked out.
- A mobile device continues trying an old password.

## Troubleshooting Workflows

1. Verify the user's identity using approved procedures.
2. Check account status and lockout state.
3. Reset password or unlock account according to policy.
4. Help the user update saved credentials on devices and apps.
5. Document the action without recording password values.

## Documentation Examples

- Record identity verification method, account state, and action performed.
- Note suspected lockout source if identified.
- Never include passwords or sensitive authentication secrets.

## Ticket Note Examples

**Issue:** User account locked repeatedly after password change.

**Technician notes:** Verified identity, unlocked account, and reviewed common saved credential locations with user.

**Resolution:** User updated saved password in mobile email profile and VPN client. Account remained unlocked after testing.

## Key Takeaways

- Password work requires strong identity verification.
- Repeated lockouts often come from stale saved credentials.
- Tickets should document actions without exposing sensitive information.
