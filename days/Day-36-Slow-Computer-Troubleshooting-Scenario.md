# Day 36 - Slow Computer Troubleshooting Scenario

**Status:** Lesson Completed

## Learning Objectives

- Build a complete workflow for slow computer reports.
- Use Windows tools to identify performance causes.
- Document performance troubleshooting with evidence.

## Concepts Learned

- CPU, memory, disk, startup apps, storage capacity, updates, malware indicators, and thermal symptoms.
- Task Manager and startup impact review.
- Difference between device performance, application performance, and network delay.
- User impact and urgency for performance tickets.

## Real-World Help Desk Examples

- A laptop takes a long time to start every morning.
- Applications freeze when many browser tabs are open.
- A device is slow because disk space is critically low.

## Troubleshooting Workflows

1. Ask when slowness occurs and which applications are affected.
2. Review Task Manager for CPU, memory, disk, and startup impact.
3. Check storage capacity, updates, and security status.
4. Disable approved nonessential startup apps or repair specific software.
5. Restart, retest, and document before-and-after results.

## Documentation Examples

- Record resource usage, free disk space, startup apps changed, and update status.
- Note whether the issue appears device-wide or application-specific.
- Include user confirmation after restart and testing.

## Ticket Note Examples

**Issue:** User reported laptop slow after sign-in.

**Technician notes:** Reviewed Task Manager, found high startup impact apps, checked disk space, and confirmed Windows updates were current.

**Resolution:** Disabled approved nonessential startup apps and restarted device. User confirmed faster startup and improved response.

## Key Takeaways

- Slow-computer tickets need data, not assumptions.
- Startup apps, low storage, and high memory usage are common causes.
- Before-and-after documentation shows the value of the fix.
